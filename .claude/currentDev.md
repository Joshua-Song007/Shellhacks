### crates/ledger-client/src/client.rs (FR-L-5, CON-1/2, FR-R-9, CON-9)
- `pub const MAX_CHUNK_BYTES: usize = 900` — duplicated from soldier's gene_compile.rs (~900B post-overhead budget, CON-9); ledger-client has no dependency edge onto soldier per architecture.md, so this is independently declared, not reused. NOT the same thing as `t_cell::MAX_GENE_BYTES` (4096) -- that's the account's total fixed space, this is a per-transaction slice size
- `LedgerClient { rpc: RpcClient, program_id: Pubkey }`; `new(rpc_url, commitment: CommitmentConfig)` and a `devnet(commitment)` convenience constructor (`https://api.devnet.solana.com`). FR-L-5 allows confirmed OR finalized -- exposed as a param rather than hardcoded, since the spec explicitly names both
- `submit_threat(reporter: &Keypair, threat_id, behavioral_schema_hash) -> Result<Signature, LedgerError>` — builds+sends via t_cell::instruction::SubmitThreat/accounts::SubmitThreat, same shape as Phase 4's litesvm test
- `commit_gene(payer: &Keypair, committee: &[&Keypair] (1-5), threat_id, gene_hash, gene_bytes) -> Result<Vec<Signature>, LedgerError>` — rejects up front if `gene_bytes.len() > t_cell::MAX_GENE_BYTES`; splits into `MAX_CHUNK_BYTES` slices via a small pure `plan_chunks(bytes) -> Vec<&[u8]>` helper (unit-testable without network); sends one commit_gene call per chunk, `is_final_chunk` on the last; `committee` padded to 5 slots by repeating the last entry if fewer than 5 given (matches t_cell's poi::require_poi tolerance for repeats — same pattern as Phase 4's tests)
- `suppress_gene(payer: &Keypair, committee: &[&Keypair] (1-5), threat_id) -> Result<Signature, LedgerError>` — same committee-padding
- `fetch_threat_registry(threat_id) -> Result<Option<t_cell::state::ThreatRegistry>, LedgerError>` and `fetch_genome_registry(threat_id) -> Result<Option<t_cell::state::GenomeRegistry>, LedgerError>` — RPC light-client reads (FR-L-5) at the client's configured commitment; `get_account_data`'s AccountNotFound maps to `Ok(None)`, not an error (a threat/gene simply not yet reported/committed is a normal state, not a failure). Returns t_cell's own state types directly rather than duplicating them as separate "view" structs, since ledger-client already depends on t_cell
- `LedgerError { Rpc(ClientError), Deserialize(anchor_lang::error::Error), GeneTooLarge(usize) }`
- NOTE for later: architecture.md says mesh needs an "async chain lookup" (Phase 6, unbuilt) — this client is synchronous (`solana_client::rpc_client::RpcClient`, matches everything else in this project, no async runtime anywhere yet); when mesh gets built it'll need to wrap calls in `spawn_blocking` or this client gets a nonblocking variant added. Not solved now, flagged for Phase 6
- FR-L-7 (Soldier checks Epigenetic_Status before running a gene) is still NOT wired into soldier itself — soldier has no dependency edge onto ledger-client per architecture.md's dependency graph; `fetch_genome_registry` is the read path a future soldier->ledger-client wire-up would use, but that wire-up isn't part of this checklist item and isn't being added here.
