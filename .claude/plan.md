Validated against the SPIKE-1 capture in crates/scout/tests/fixtures/; not yet run live under root)
- [x] crates/scout/src/reader.rs — dedicated thread reads raw stdout lines into bounded channel before JSON deserialize/TES normalization, so parsing never backpressures the OS pipe; explicit drop policy, drops counted + surfaced alongside seq-gap drops (FR-D-7a, NFR-7) (policy = drop newest when full; capacity 65,536 lines; each line stamped with arrival ns = TES `recv_ns`)
- [x] crates/scout/src/bin/ac2_bench.rs — AC-2 harness: repeatedly spawns a benign short-window behaviour (process exec'd from a temp dir whose lifetime ≪ the poll interval), runs an `lsof`-polling baseline detector at a fixed interval alongside the event-driven Scout path, reports catch-rate + median detection latency for both (AC-2; the polling baseline is measurement-only and never on Scout's detection path, FR-D-1; needs root for the eslogger side) (probe = a copy of `/bin/sleep` per run, exec'd from `/tmp/tcell-ac2-<pid>/`; correlates both detectors by pid via a shared map; eslogger side reuses `scoring::exec_actions` (Scout's own rule); lsof side runs `lsof -d txt -Fpn` and matches the probe's own path; a fixed-seed LCG jitters the gap between trials so they don't phase-lock with the poll interval; unit-tested only (parser/median-p95/jitter bound), the live spawn/detect loop needs root and is not run in CI. Not yet run live)
- [x] crates/tes — no `connect`/network event kind added: considered for the beacon lane below, rejected because TES v1 models a lossless nanosecond-precision stream and an `lsof` poll is neither (see source_beacon.rs note); overview.md FR-D-11 updated 2026-09-26 to match (user-approved edit)
- [x] crates/scout/src/source_libproc.rs — degraded path: libproc proc_listpids/proc_pidinfo + kqueue EVFILT_PROC + FSEvents, event-driven, no lsof; pidver derived via proc_pidinfo(PROC_PIDTBSDINFO)->pbi_start_tvsec, not PROC_PIDTASKINFO (FR-D-3, FR-D-7) (`scout --libproc [--watch DIR]` (default $HOME); FSEvents never names the process, so file events are INFERRED: the batch goes to the watched process holding >=80% of `ri_logical_writes` bytes over the trailing 1s (window, not per-batch, because FSEvents arrives after the writes), else counted unattributed; inferred actions are marked in Detection `inferred` + stats and never enter Threat_ID. Limitations: without root, start time/argv/rusage are readable for own-uid processes only — other-uid pidver is a Scout counter, their writes are unattributable, their shells count as lineage boundaries (no args); pidver = start time in µs, not bare pbi_start_tvsec (seconds collide); no NOTE_TRACK so a child that forks/execs before registration loses that step; ts_ns = delivery time (kqueue/FSEvents carry none); platform=false always; one TES event per FSEvents entry (coalesced flags under-count ops); rusage ignores rename/unlink so rename-only bursts are missed, unpaired renames counted; a writer that exits before its batch is not credited; attribution can credit the wrong own-uid process if it also wrote heavily in the window. No revisit scheduled; live run under the demo setup still pending)
- [x] crates/scout/src/source_beacon.rs — separate periodic lsof -i collector, network lane only, not on eslogger (FR-D-11, CON-5) (findings go to their own `network_finding` stdout records, not TES/Pipeline — see the tes note above; `--beacon [SECS]` (default 5s), runs alongside any source; beacon = same (pid,remote) reconnects >=3 times with inter-arrival spread <=20% (T1071); scan = one pid opens >=20 new distinct remotes in one snapshot (T1046); each finding's time is a `[from,to]` snapshot window, not a point ts_ns, since a poll cannot say when inside it a connection opened; first snapshot only baselines, raises no findings, so pre-existing connections at startup are not flagged; a connection that opens and closes between two snapshots is invisible; without root only own-uid `exe` paths resolve (via source_libproc::exe_path); stats key "beacon". Not yet run against a real repeating connection)
- [x] crates/scout/src/lineage.rs — lineage rollup via fork/exec, identity=(pid,pidver) discriminates recycled PID, survives single PID exit (FR-D-7) (overview.md does not define where a lineage starts: children of launchd, session hosts (login/sshd/Terminal/iTerm/Finder/Dock/loginwindow) and interactive shells (no script/-c/-s arg) start new lineages, everything else rolls up — so typed terminal commands don't accumulate into one trajectory; a fork event lost to a kernel drop orphans the child into a new lineage; no revisit scheduled)
- [x] crates/scout/src/scoring.rs — Stage-1 weights table (ExecFromTempOrCache=20, RecoverySnapshotTamper=50, RapidFileModBurst=40), threshold>=100 -> SIGSTOP lineage + emit {Threat_ID,pid,schema}; Threat_ID=SHA256(ordered action bytes), deterministic; never suspend own PID/below system floor (FR-D-8/9/10) (each action counts once per lineage, so crossing 100 requires all three; action bytes 1/2/3, Threat_ID pinned by test; RapidFileModBurst = >=64 write-open/create/rename/unlink in 1s; tamper = `tmutil delete|deletelocalsnapshots|thinlocalsnapshots|deleteinprogress`, `diskutil apfs deleteSnapshot`; temp prefixes include /private/* canonical forms; system floor = pid < 100 plus Scout + eslogger pids; wake `pid` = pid of the tipping action, `schema` = ordered action names; pid reuse between a lagging exit event and SIGSTOP is not guarded; no revisit scheduled)
- [x] crates/scout/src/pipeline.rs — source-agnostic per-event wiring TES boundary -> lineage -> scoring -> suspend; builds Detection {wake, root_exe, score, attack_ids, suspend report, latency_ns = suspend time − tipping action ts_ns (NFR-1)}; retires lineages whose members all exited (not in original checklist: split from main.rs so the pipeline is testable without root)
- [x] crates/scout/src/main.rs — Scout daemon: wire sources -> reader -> tes::validate -> lineage -> scoring; no polling shell-out on process/file path (FR-D-1, NFR-1/2) (sources: live eslogger (default), --eslogger-file, --tes-file replay; --dry-run records instead of SIGSTOP; --wake-socket PATH sends WakeSignal as one JSON line over a Unix stream; stdout = NDJSON `detection`/`stats` records; not yet run live under root)
